# Design

## Context

見 `proposal.md`。本專案為 AirGuard AI 的核心架構設計，面臨的主要約束包括：空氣品質資料的高度非線性與突發性、使用者在對話查詢時的低延遲需求（< 2秒端到端）、以及醫療與健康指引領域對「零容忍幻覺」的極高安全性要求。

## Goals / Non-Goals

**Goals:**
- 構建微服務架構（FastAPI），將預測引擎、環境數據服務與 Agent 職責解耦。
- 實作基於 LightGBM 的 1–6 小時短期空氣品質時間序列回歸模型，推論時間控制在 200ms 以內。
- 建立以 Pydantic Schema 為基底的嚴格工具調度介面（Function Calling）。
- 實作基於台灣環境部官方指引的確定性規則引擎與生成後數值審查攔截器（Post-generation Guard）。
- 提供支援 2024–2026 台中測站數據的滾動回測評估模組與 30 組場景基準測試集。

**Non-Goals:**
- 不涉及大規模物理擴散數值模擬（如 WRF-Chem 或 CMAQ 網格運算），聚焦於統計機器學習短程預報。
- 不提供侵入式持續背景 GPS 軌跡追蹤，僅採用會話級地理位置或測站名稱指定。
- 不取代專業醫療診斷與處方開立，所有輸出均定性為「健康生活與戶外活動防護建議」。

## Decisions

### 1. 預測架構選擇：輕量梯度提升樹（LightGBM） vs. 複雜時空圖神經網路（ST-GNN）
- **決策**: 採用 LightGBM / XGBoost 多步直接回歸（Direct Multi-Horizon Regression）。
- **理由**: 戶外活動諮詢場景需要極高的推論反應速度（< 200ms），LightGBM 能高效利用測站時間滯後（Lag）特徵與氣象特徵，在滾動回測中展現優異的 MAE/RMSE，且易於在 CPU 環境中輕量化部署。
- **替代方案**: 時空圖神經網路（ST-GNN / Informer）具備更強的區域擴散建模能力，但計算資源依賴度高、延遲顯著，適合作為未來擴展之離線批次預報，而非即時工具調用首選。

### 2. Agent 編排策略：嚴格工具調用（Function Calling） vs. 自由對話微調模型
- **決策**: 採用 LangChain / LangGraph 配合商用或開源具備 Tool Calling 能力的 LLM（如 Gemini / GPT），並以 Pydantic 嚴格定義工具協定。
- **理由**: 環境指標隨時間動態變化，語言模型的內部權重無法記憶即時環境數據；透過強制 Tool Calling 能確保所有數值皆源自客觀工具查詢，徹底消除數值記憶錯誤。
- **替代方案**: LoRA 微調氣象專業模型成本高昂，且仍無法避免即時數據「知識陳舊（Knowledge Cutoff）」與數值幻覺問題。

### 3. 安全防護：雙層混合架構（確定性規則 + LLM 上下文合成）
- **決策**: 在 LLM 輸出前後設置「確定性防護層」。輸入前透過規則引擎計算標準風險級別，輸出後透過正規表示式與資料比對器驗證數值一致性。
- **理由**: 涉及公眾健康的活動建議絕不能單純依賴 Prompt 的軟性約束，必須具備確定性的程式碼硬性安全邊界（Hard Guardrail）。

## Risks / Trade-offs

- **[Trade-off 1] 預測精確度 vs. 推論延遲**:
  - *風險*: 追求更高精度的複雜集成模型會導致對話等待時間過長。
  - *緩解*: 建立 10 分鐘滑動特徵快取機制，預測模型採用預先特徵工程與輕量回歸，確保單次推論低於 200ms。
- **[Trade-off 2] 對話靈活性 vs. 臨床安全**:
  - *風險*: 過度限制 Prompt 會降低對話親和力，但放寬生成又可能產生未授權的醫療承諾。
  - *緩解*: 採用「數值與規則硬約束，語氣與陪伴軟生成」的解耦設計；對話維持同理心，但禁言詞庫與數值校驗器嚴格執行過濾。
- **[Trade-off 3] 個人化粒度 vs. 使用者隱私**:
  - *風險*: 精細的健康病史與軌跡記錄可能引發個資與隱私疑慮。
  - *緩解*: 僅採集臨時會話級生理標籤（如敏感族群分類：呼吸道、心血管、年長者），對話結束後即銷毀詳細特徵，不持久化儲存可識別個人資訊（PII）。

## Migration Plan

1. 部署底層資料管線與測站快取服務。
2. 訓練並持久化 2024–2026 台中測站預測權重與標籤特徵。
3. 發布 FastAPI 微服務並掛載 Pydantic 工具端點。
4. 部署 Agent 與確定性安全驗證中介軟體。
5. 執行 30 組基準場景自動化評估，通過驗證後上線。
